## Project orientation

AMS is an attendance management system for three roles: **ADMIN**, **FACULTY**, and **STUDENT**. The intended product supports authentication/RBAC, academic structure and scheduling, faculty attendance, facial recognition with manual fallback, analytics and attendance recovery, leave/regularization with evidence, notifications, auditing, and deployment.

### Current architecture

- **Frontend:** `frontend/` is a Vite + React + TypeScript single-page application. API requests are in `frontend/src/services/api.ts`; the API base is `VITE_API_BASE_URL`, defaulting locally to `http://localhost:8000`. Requests use credentialed cookies.
- **Design system:** Solaris Hybrid Editorial is represented in `frontend/src/index.css`: Plus Jakarta Sans, JetBrains Mono, warm paper surfaces, orange `#FF5722`, coral `#FF8A65`, and dark ink surfaces/text. The supplied frontend was redesigned toward these tokens.
- **Backend:** `backend/app/` is FastAPI, Pydantic, SQLAlchemy, PostgreSQL/pgvector, and Alembic. `backend/app/main.py` registers routes; `backend/app/api/` contains role/domain routes; `services/` owns business rules; `models/` and `schemas/` describe persistence/contracts; `vision/` isolates recognition; `workers/` handles notifications.
- **Database:** PostgreSQL 16 with pgvector, run locally by Docker Compose. Demo fixtures are synthetic and generated by the development-only idempotent seeder. The application must read/write the database; `frontend/src/data/mockData.ts` exists but should not drive current UI behavior (no active imports were found in the last source check).
- **Live events:** WebSocket `/ws/attendance/{session_id}` is used for an open faculty attendance session. Camera frames are submitted by authenticated HTTP multipart upload to `/api/faculty/attendance/session/{id}/recognize`.
- **Files and external services:** Request evidence is stored through an adapter; production should use private S3-compatible storage, not an ephemeral Render filesystem. Notifications run through a worker and optional SMTP/Twilio providers.
- **Local services:** `docker-compose.yml` defines `db`, `backend`, and `worker`; frontend runs separately from `frontend/`.

### Architecture decision

The locked system design originally calls for Next.js. The supplied app is Vite/React and the owner accepted keeping Vite for this release in `docs/adr/0001-retain-vite-for-release.md` because Vercel setup is underway. **Do not migrate frameworks as part of this handoff.** Treat this as a scoped, documented deviation; a future Next.js migration needs a separate owner decision and plan.
